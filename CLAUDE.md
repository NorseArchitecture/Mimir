## What This Realm Is

Mímir is **the serving layer** for the platform's reference data — the head Odin carries for counsel, consulted wherever it goes: nobody needs the well itself (Mímisbrunnr) to get an answer. All projects are pure NuGet classlibs — nothing here is a standalone host; everything spins up from Yggdrasil's composition root (declare in a realm, host in Yggdrasil, compose in Bifröst).

| Project | Carries | Rule |
|---|---|---|
| `Reference.Contracts` | The wire records (`CountryRequest`/`CountryResponse`), `IReferenceService`, and `ReferencePolicies` (names only) | Thin by law — pure `[DataContract]` shapes in the flat `Norse.Reference` namespace, shared with Mímisbrunnr's baked surface so one `@using` covers both |
| `Reference.Web.Server` | The gRPC `IReferenceService` implementation: server-sovereign command wrappers + handlers over Mímisbrunnr's entities, registration generated by Asgard's `Generator="true"` NorseRef | Server-only; policy names are mirrored onto gRPC methods for endpoint metadata — registration happens at Yggdrasil's composition root, never here |
| `Reference.Components` | Routable Blazor components over the wire contract — `CountryLookup` (migrated home from Yggdrasil's `Hosting.Web.Components`, 2026-08-09) | NORSE073-governed: consumes foundation and published surfaces only. Any referencing host discovers its routes at compile time (`AddNorseClientComponents()`) — no per-host registration edit exists |
| `.Worker` | Declared, not yet built — the background worker that will keep ISO/IANA data current at runtime | Data freshness is this project's future job, never a release event (see the SemVer contract) |

**Dependency posture:** rides Mímisbrunnr's published surfaces (`Reference.Data.Contracts` via `Reference.Contracts`, `Reference.Data.EntityFramework` from `Reference.Web.Server` only) and Asgard's law; Yggdrasil's hosts ride on *it*, not the other way around. The README's chart draws it; transitive-first holds throughout — the baked browser-safe surface reaches `Reference.Components` through `Reference.Contracts`, no direct edge.

**Mímisbrunnr is the companion repository** — one bounded context, two repositories, sharing the `Norse.Reference.*` namespace root deliberately. The split exists for exactly one reason (verified 2026-07-03 against Ginnungagap's `publish-nuget.yml`): release tooling is repo-scoped — a tag packs and publishes a whole repo — and reference-data content churns far faster than serving code. Not the platform's default recommendation; do not copy the split reflexively.

## Architecture Facts (decided — do not re-litigate)

- **The generated surface is authored in Mímisbrunnr, never here.** `IsoCountryCode`, `Iso3166`, and `ReferenceNamespaces` generate in Mímisbrunnr (`Reference.Data.Contracts`/`.Namespaces`) and arrive by reference. Mímir's own generator project and `Reference.Seeds` are gone — moved to Mímisbrunnr; never reintroduce either.
- **`Reference.Data.Contracts` is named for what it is (renamed from `.Data.Primitives`, 2026-08-09).** The rename was forced honestly: NORSE073 struck the first realm Components RCL that consumed it, because "Primitives" classified as neither foundation nor published surface — and collided with the forge's vocabulary word besides. The persistence side publishes *wire-safe contracts*; the dwarves' `Result<T>` still hammers them into values or problems. Do not reintroduce a `Primitives`-named assembly outside Svartálfheim.
- **`Reference.Components` is transport-dumb and host-blind.** It injects `IReferenceService` and consumes `Task<Outcome<T>>` by pattern-matching; which implementation stands behind the contract is each host's DI decision. Routes are discovered from the reference closure at compile time — referencing the assembly *is* the registration.
- **The interop boundary is Mímisbrunnr's entities and view models, and SemVer there is a pure schema-contract signal:** patch/minor (new rows, non-breaking additions) needs no reaction here; major means the shape changed — the one event that forces this realm to update. Routine data freshness (next tzdata, a new ISO currency) is neither a Mímisbrunnr release nor a Mímir release — it's `Worker`'s future runtime job against the existing schema.
- **Policy names registered at Yggdrasil, never here.** `ReferencePolicies.Public` follows the same law as `AuthNPolicies.Public`: this realm names it and mirrors it onto gRPC methods for endpoint metadata; the composition root registers what satisfies it.
- **This pair is the platform's reference-data template** — Mímisbrunnr proves the substrate needs zero new framework code; Mímir proves the serving layer is three thin projects and a chart.
